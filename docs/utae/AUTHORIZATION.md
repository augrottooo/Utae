# 认证、授权与数据隔离

## 身份

目标实现使用 HttpOnly、Secure、SameSite Cookie 的服务端会话。Spring Security 从会话解析用户和角色，Controller 不接受客户端传入的 user scope 作为授权依据。

## 权限矩阵

| 行为 | 未登录 | 普通用户 | 所有者 | 维护者 |
| --- | --- | --- | --- | --- |
| 浏览已发布共享歌曲 | 可按产品策略只读 | 是 | 是 | 是 |
| 读取私人歌曲 | 否 | 仅本人 | 是 | 按维护任务授权 |
| 上传和创建制作任务 | 否 | 是 | 是 | 是 |
| 修改/删除私人歌曲 | 否 | 仅本人 | 是 | 需审计 |
| 复核/发布共享版本 | 否 | 否 | 否 | 是 |
| 创建复习任务 | 否 | 仅本人 | 仅本人 | 仅在明确代理权限下 |
| Agent Tool 调用 | 否 | 受限 | 受限 | 受限 |

每个 Service 都要重新校验 song、version、line 的归属关系；不能只检查 URL 中的 ID。收藏、学习进度和 Agent 读取都必须带当前 user id。

Studio 制作辅助 Agent 是可选的外部宿主角色，只能整理任务证据；alignment `accept` 必须由有权限的上传者（仅私人歌）或维护者提交审核决定。Learning Agent 不持有制作任务权限。Cookie 写操作使用 CSRF 防护，退出时撤销服务端会话；前端的 userId/role 只用于展示，不作为授权输入。

## 资产访问

Manifest 由 Java 根据权限生成。MinIO object key 只存服务端；浏览器使用 Java 代理 Range 或短期签名 URL。签名 URL 不写入日志和 Agent Trace。删除或撤回版本时先更新业务状态，再按引用计数清理对象。

## 上传保护

限制大小、扩展名和 MIME，服务端实际探测音频；流式计算 SHA-256；文件写入隔离临时目录；解压/歌曲包校验拒绝路径穿越和超大资源。错误返回统一 code，不泄露本地路径或模型密钥。

正式认证、CSRF、会话续期和维护者账号初始化属于阶段 3 实现项，本轮没有实现或验证。
