# Utae 产品需求（方案基线）

## 定位

Utae 是面向日语歌曲精听和发音练习的平台。歌曲是练习材料，不把产品扩展成综合日语课程或社交音乐平台。

核心闭环：

```text
歌曲制作 -> 候选包复核 -> 歌曲库 -> 精听/逐句练习 -> 学习记录 -> 复习建议
```

## 用户与权限

- 普通用户：浏览已发布共享歌曲，管理自己的私人歌曲、收藏和学习记录。
- 歌曲所有者：编辑私人歌曲元数据、提交制作任务、查看任务状态和修订候选包。
- 维护者：复核共享候选包的来源、歌词、版权/许可、播放证据，执行 Utae publish approval 或撤回共享歌曲。
- 未登录用户：只能访问明确公开的只读内容；不能上传、写入学习记录或调用写工具。

歌曲制作中的可选“制作辅助 Agent”属于 Sorane Studio 宿主角色，可整理来源/候选证据和疑点；它不能批准发布。Learning Agent 仅作用于用户学习数据，不能参与歌曲检索、歌词核对或成品审批。

正式身份来自服务端会话，不能使用固定开发用户 ID。

## MVP 功能

### 歌曲库

- 基础曲库和我的歌曲分开显示。
- 初始基础曲库由维护者准备 3–5 首有来源/使用权记录并经过试听验收的示例歌曲。
- 按标题、歌手、状态搜索；显示当前发布版本和制作状态。
- 私人歌曲默认不公开；共享歌曲必须由维护者发布。
- 歌曲包版本不可变，修改产生新 `packageVersion`。

### 歌曲制作

- 上传音频和歌词，服务端校验类型、大小和 SHA-256。
- 创建可追踪的制作任务，展示阶段、进度、错误和重试入口。
- Worker 通过 Sorane Studio CLI/Adapter 执行确定性阶段；不能自动搜索资料、核对歌词、听音决策或发布。
- 对齐证据缺失时进入 `NEEDS_REVIEW`，上传者/维护者在原 Studio task 上补充资料和报告并恢复。
- 分别记录 Studio alignment review/`accept`、playback review 和 Utae publish approval；只有最后一个门禁通过才发布。
- 处理失败不删除原始上传，支持从已完成阶段恢复。

### 精听与练习

- 复用 Sorane Player 的音频时钟、歌词同步、分块加载、缓存、混音、全曲/逐句/逐段、循环和速度能力。
- 罗马音为主要辅助读音；歌曲包已有的中文翻译可选显示。
- 原曲、人声、伴奏和朗读切换只在歌曲包确实提供对应资产时显示。
- 练习行为产生有意义的学习事件；播放进度保存不等于学习事件。

### 学习与 Agent

- 保存播放进度、收藏句子、最近练习和复习任务。
- 一个 Learning Agent 查询真实用户数据并给出复习建议。
- Agent 只能调用白名单工具，记录 Run、Step、Tool Call Trace。

## 关键流程

### 普通练习

```text
登录 -> 曲库 -> 歌曲详情 -> 获取已授权 Manifest -> PlayerBridge 加载
  -> Sorane 音频时钟驱动歌词 -> 保存进度/学习事件 -> 可收藏句子
```

### 制作与发布

```text
上传 -> 输入修订 -> Job -> Outbox/MQ -> Worker 调用 Studio
  -> NEEDS_REVIEW -> 人工 alignment review -> Studio accept -> run 生成包
  -> 私有 candidate -> playback review -> Utae maintainer approval -> publish -> 曲库可见
```

Studio `accept` 只批准对齐报告；Studio `install` 只复制到隔离本地验收库，不代表 Utae 发布。

## 不纳入 MVP

不做自动发音评分、语法课程、完整词典、自动歌词强制对齐、公开投稿、社区、排行榜、复杂学习计划、多 Agent、RAG 向量库和 Kubernetes/微服务治理。人声分离、对齐和朗读生成只复用 Studio 已有能力，不在 Utae 中自行研发模型。

## 验收摘要

MVP 必须能以真实歌曲包完成播放、同步歌词、逐句/逐段练习和学习记录；上传链路必须能看到候选包、失败恢复和人工发布边界；Agent 的建议必须能回溯到真实学习数据。完整条目见 [ACCEPTANCE.md](ACCEPTANCE.md)。
