日期：2026-11-17。开发基线：`main` / `5fc320442ef78d1fdb771e36e7a12f0b60d07b99`。1A、1B 已完成并推送，checks #4、demo #4 成功及 1B 网页验收通过为用户确认事实。本轮不重复要求 1B 手测。

## 范围与结果

原路线图未单列 1C；本轮依照用户指令将其限定为阶段 1 的歌曲包加载/兼容性收尾，并在路线图明确交付物和依赖。实现、自动化检查及真实公开歌曲包的桌面功能验证已通过；完整逐词听审、混音听辨和移动设备矩阵仍未覆盖。

- `validate.ts` 对未知 JSON 验证 schema、唯一 ID、三档音频、句/词时间与裁切、可选读音、ruby/readingParts、分块覆盖/帧数/时长及包内资源路径。沿用 schema 1，不修改 Python 契约；保留未知扩展字段。
- `load.ts` 区分 HTTP、JSON、schema 失败；校验后解析相对 URL，并将 chunks 键、parts、读音和整曲 fallback 一起映射。只预检所选歌曲，最多同时 4 个请求，HEAD 不支持时 Range 后取消响应体。
- 本地目录与练习页共用 catalog，支持空目录、加载/失败/重试、未知歌曲。预检失败不创建 Host；离页取消，返回缓存歌曲等待重新检查，旧异步成功不得挂载过期页面。
- `SoranePlayerHost` 隔离旧会话 play Promise 拒绝；原有订阅销毁、StrictMode 重挂与新 audio 节点仍由既有 Bridge/Host 实现。React 不维护音频时钟、循环或播放状态。
- `prepare-player-assets.mjs` 在发布曲库前检查全部引用文件非空、实际目录边界和 SHA-256 前缀，复制引用资源并修复损坏的已准备副本。源资产失败时保留已有 catalog。命令可接收隔离的源/目标目录；不清理无引用历史资产，不承诺整个目录事务性替换。

## 尚存限制与后续验收

- 真实公开包的桌面功能已验证；完整逐词听审、混音声道听辨、其他真实包和移动设备矩阵仍未覆盖。不要求重做用户已通过的 1B 页面/路由验收。
- HTTP 预检只证明当时可访问/非空/非 HTML；不证明媒体可解码或时间标注正确。Range 被服务器忽略时，取消响应体也不能保证仅传一个字节；播放中网络和解码错误继续由 Sorane 原机制处理。
- 固定 DOM ID/全局 CSS 仍限定每个 document 一个活跃播放器；缓存/解码器后台工作保持原清理边界，不宣称浏览器堆快照或所有后台请求全量取消。
- 本地 catalog 按既有页面会话缓存；新增/替换整个构建曲库后刷新页面。没有新增业务版本 API、权限、上传、后端或部署工作流。

本轮未修改上游音频核心、Python schema/build、依赖/锁文件、CI 或系统环境。没有执行 Git 暂存、提交、推送、合并、变基或 reset；所有改动保留为本地未提交候选。
